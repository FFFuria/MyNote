# 路径规划 / 洪涝风险 / 栅格风险场方向的可复现论文与开源仓库深度调研报告

## 执行摘要

本报告面向“路径规划 / 洪涝风险 / 栅格风险场”方向，重点筛选**可在单人/小团队、有限算力、三个月内完成“完整代码复现”**的研究工作：要求尽量同时具备**论文原文、官方或明确可复现实验的代码仓库、公开数据（或可下载脚本）、环境说明（requirements/conda/docker/版本）、训练/测试脚本或可运行 demo**。在此标准下，最终给出 **12 个候选项目**，覆盖你指定的四类优先主题：  
1) 栅格风险/代价预测（CNN/U-Net 等）→ A_/Dijkstra 路径；_  
_2) 强化学习网格路径规划（PPO/DQN 等）可跑通的训练/评估脚本；_  
_3) GNN 用于图上路径/代价学习（道路网络轨迹外推、最短路推理等）；_  
_4) 端到端（或“可微规划”）学习路径（Neural A_ / GPPN / WPN 等）。

综合“复现闭环完整性 + 数据可得性 + 环境可落地性”三项指标，最推荐从易到难优先复现：**DeepWay（含A _notebook）→ Neural A_（官方Docker/脚本/数据生成齐）→ ML4Floods（WorldFloods/样例数据+训练教程）**；其中 DeepWay 与 Neural A\* 更适合快速建立“风险场→规划”的统一代码框架，ML4Floods 更适合作为“洪涝风险栅格场”真实数据端的基线与扩展入口。[\[1\]](https://github.com/fsalv/DeepWay)

## 检索范围与筛选标准

检索与优先来源（按优先级与可复现价值排序）：  
首先查阅论文与基准的索引站点（如 Papers with Code[\[2\]](https://github.com/spaceml-org/ml4floods)），再以 arXiv[\[3\]](https://github.com/jbcdnr/gretel-path-extrapolation) 原文与 GitHub[\[4\]](https://github.com/perfectly-balanced/PathBench) 官方/作者仓库为准；与数据强相关的项目优先选择有 Zenodo[\[5\]](https://github.com/fsalv/DeepWay)、公开云存储（例如 GCS/gsutil）、或明确下载脚本/样例数据的仓库；工程与复现导向的基准平台（如 PathBench/Minigrid）优先；与 DEM/地形相关的数据入口在方法论层面纳入 OpenTopography[\[6\]](https://github.com/omron-sinicx/neural-astar) 等（本次候选中主要使用论文/仓库自带的 DEM/地形特征与公开数据指引）。[\[7\]](https://arxiv.org/abs/2105.01777)

筛选标准（用于判定“完整可复现”的实操门槛）：  
重点核查仓库 README/教程中是否明确提供：依赖/版本（requirements.txt、conda 脚本、Dockerfile、或至少 Python+框架版本）、数据获取方式（下载脚本/命令/公开链接/内置数据生成器）、训练入口（train.py 或等效脚本/Notebook）、评测入口（eval.py/test.py 或 notebook 的测试段）、以及关键配置文件位置（config / parameters / dataset loader）。若信息缺失，则在表格中标注“未提供”，并给出替代复现策略（例如：用合成数据/小样本替代、或先跑作者 demo）。[\[8\]](https://github.com/omron-sinicx/neural-astar)

## 分类代表项目与复现步骤

本节按你指定的四类优先方向，各给出 2–3 个**代表性且可操作**的复现路线（尽量提供数据下载命令/入口与关键文件定位）。为避免“给出完整代码实现”，以下仅给出可复现路径与仓库定位。

**基于栅格的风险/代价预测（CNN/U-Net）+ 用 A\*/Dijkstra 做路径**

代表项目一：ML4Floods（WorldFloods 洪涝分割 → 风险栅格）  
1) 先用官方训练教程跑通“样例数据→训练→评估”闭环：教程明确给出“下载样例 zip（约 12.7GB）→配置→Lightning 训练→评估”的流程，并在无法挂载 Drive 时使用 gdown 下载。[\[45\]](https://spaceml-org.github.io/ml4floods/content/ml4ops/HOWTO_Train_models.html)  
2) 风险场构造：将模型输出的 flood mask（或多类别 water/cloud/land）映射为代价（例如 water=高代价、cloud=不可通行或不确定性代价）。这一转换不在仓库中“固定提供”，但 ML4Floods 明确把输出作为像素级分割掩膜，适合作为栅格代价场输入。[\[46\]](https://github.com/spaceml-org/ml4floods)  
3) 路径规划：在你自己的脚本中对代价栅格运行 A\*/Dijkstra（例如用栅格邻接图或栅格上的启发式搜索），输出路径与累计风险代价；随后与作者指标（分割 IoU/F1 等）并行汇报，形成“风险预测 + 规划”的联合复现报告。

代表项目二：RituYadav（SAR+DEM+PW 融合分割 → 更“地形一致”的风险栅格）  
1) 下载数据：对应 Zenodo 记录提供 PRE/POST 与 labels 三个压缩包（页面有“Download all”与单文件下载按钮）。[\[47\]](https://zenodo.org/records/7946594)  
2) 训练/评估：仓库直接以 flood.py 作为训练与评估入口：python3 flood.py train / python3 flood.py evaluate；你需要在脚本中配置数据路径、权重路径等。[\[48\]](https://github.com/RituYadav92/Uni-Temporal-Flood-Detection-Sentinel-1_Frontiers22)  
3) 复现要点：该工作强调 DEM 与永久水体信息可减少不合理的高坡度误检，因此你的复现报告建议同时输出：分割指标 + “坡度/高程分段的误检率统计”，为后续“风险代价场”提供更合理的空间先验。[\[49\]](https://www.frontiersin.org/journals/remote-sensing/articles/10.3389/frsen.2022.1060144/full)

代表项目三：DeepWay（“代价/可通行栅格→航点→A_”的完整最小闭环）_  
_1) 可运行性：仓库提供合成数据生成 notebook、训练 notebook、测试 notebook，以及直接运行 A_ 生成路径并计算覆盖指标的 notebook（非常适合三个月内做“可复现工程”）。[\[31\]](https://github.com/fsalv/DeepWay)  
2) 建议复现切入：先只用合成数据跑通 waypoint 预测与 A\* notebook，锁定环境与结果；再把“洪涝风险栅格”替换合成栅格输入（保持同样的接口与评估输出），即可把该项目变为你的“栅格风险场→规划”的可复现骨架。[\[31\]](https://github.com/fsalv/DeepWay)

**强化学习用于网格路径规划（DQN/PPO 示例）**

代表项目一：Minigrid + RL Starter Files（快速跑通 PPO/A2C，并可加自定义风险奖励）  
1) 环境：Minigrid 提供一组网格导航/指令环境，论文与项目均强调其“可扩展、易安装”的设计目标。[\[50\]](https://arxiv.org/html/2306.13831v1)  
2) 训练脚本：rl-starter-files 明确提供训练/可视化/评估三件套脚本，并给出示例命令（如 DoorKey 环境训练 PPO、可视化与评估）。[\[51\]](https://github.com/lcswillems/rl-starter-files)  
3) 迁移到“洪涝风险场”：把栅格风险值注入 observation（额外通道）或 reward（高风险惩罚/不可通行），并保持训练/评估脚本不变，只替换 env wrapper；这样能保证“复现实验格式”稳定，同时让你的创新集中在风险建模与奖励设计。

代表项目二：Stable-Baselines3 + RL Baselines3 Zoo（PPO 与 DQN 都能直接跑，利于做系统对比）  
1) SB3 本身是“可复现实验工具链”型项目（有 JMLR 软件论文背书），而 rl-baselines3-zoo 提供训练/评估/调参/绘图/视频录制脚本，适合做严格复现实验记录。[\[52\]](https://www.jmlr.org/papers/volume22/20-1364/20-1364.pdf)  
2) Zoo README 明确列出对 Minigrid 的支持与可用算法（包括 PPO，也列出 DQN/QR-DQN 等条目），可直接作为你的 Baseline Matrix（PPO vs DQN、不同 map/风险分布对比）。[\[53\]](https://github.com/DLR-RM/rl-baselines3-zoo)  
3) 复现建议：先复现“原始 Minigrid baseline 曲线/回报”作为 sanity check，再切到你的“风险场环境”（同 observation space/接口），保证论文里每一条曲线可追溯到命令与配置文件。

**基于图神经网络的道路网络代价预测或路径学习**

代表项目一：Gretel（道路网络/自然路径外推，含 Zenodo 工作区数据）  
1) 复现入口：仓库 README 给出 conda 环境创建脚本（create_env.sh），并明确数据来自 Zenodo 的 workspace.zip；目录结构与运行入口（python main.py config/wiki...）写得较清楚。[\[54\]](https://github.com/jbcdnr/gretel-path-extrapolation)  
2) 数据落地：若你只关注“道路网络上的路径学习”，优先从其 gps/wikispeedia 子任务开始，先把 workspace 下载并按要求放在 workspace/；避免一开始就改数据格式。[\[55\]](https://github.com/jbcdnr/gretel-path-extrapolation)  
3) 与“风险场”结合的可复现实验：把栅格风险场投影到道路边（edge）代价或节点风险特征，再用 Gretel 的“路径后缀预测/采样”机制做“风险引导的轨迹生成”对比（可作为扩展章节）。

代表项目二：DNAR（离散化的神经算法推理，含 Dijkstra 最短路）  
1) 仓库明确包含生成数据与训练评估脚本，并列出覆盖算法集合（包含 Dijkstra 最短路）；这是做“GNN 学最短路/代价传播”复现的高性价比入口。[\[43\]](https://github.com/yandex-research/dnar)  
2) 复现路径建议：先单任务 Dijkstra 跑通（生成数据→训练→eval），记录配置与随机种子；再做 OOD（更大图规模）外推测试，形成“可证明/可解释的算法推理”复现报告结构。[\[56\]](https://arxiv.org/pdf/2402.11628)

**端到端学习路径（若有且可复现）**

代表项目一：Neural A_（可微 A_，官方 Docker/脚本/数据生成齐）  
1) 直接跑 minimal 分支：官方 README 明确“脚本训练 + notebook 示例 + Docker 复现环境”，非常适合快速建立可复现实验工程结构。[\[19\]](https://github.com/omron-sinicx/neural-astar)  
2) 数据生成：planning-datasets 仓库给出 shell 脚本生成 MP/TiledMP/CSM 等规划数据，能把“数据→训练→评估”完全脚本化。[\[21\]](https://github.com/omron-sinicx/planning-datasets)  
3) 扩展到“洪涝风险”：把风险场作为 guidance map 的监督目标（模仿学习：专家路径来自 A\* 在风险代价上跑出来的最优路径），可形成“风险预测 vs 风险规划”的端到端对比复现实验。[\[20\]](https://github.com/omron-sinicx/neural-astar)

代表项目二：GPPN（VIN 改进版，提供精确复现场景）  
1) 复现优势：仓库既支持自己生成迷宫数据，也提供下载论文用数据集的脚本，并明确给出 train/eval 命令与参数（K、F 等）。[\[24\]](https://github.com/RLAgent/gated-path-planning-networks)  
2) 风险场迁移：把“障碍/可通行”扩展为“代价层（风险层）”，评估搜索最优性与效率 trade-off；适合与 Neural A\* 进行同平台对比。[\[23\]](https://github.com/RLAgent/gated-path-planning-networks)

代表项目三：WPN（混合：局部 LSTM + 经典 A\*）  
1) 仓库提供 Quick Start（GUI 跑法）与训练管线描述；适合你做“把风险场作为经典规划的 global cost，同时学习局部决策减少搜索空间”的复现扩展。[\[29\]](https://github.com/h2jaafar/WPN)

## 总体推荐与时间估计

以下按“单人/小团队、有限算力、三个月内完成”为约束，给出 3 个从易到难的最推荐复现对象，并给出务实的时间颗粒度（含踩坑缓冲）。

最推荐一：DeepWay（最快形成完整复现报告骨架）  
理由：仓库以 notebook 形式提供“合成数据生成→训练→测试→A\* 路径生成与指标”，环境安装与入口非常直接，且天然贴合你要的“预测 + 规划”结构。[\[31\]](https://github.com/fsalv/DeepWay)  
时间估计：  
\- 跑通环境与 notebook：0.5–1 天  
\- 复现主要结果（合成数据 + 预训练权重/自行训练）：2–4 天（含可视化整理）  
\- 写成可复现项目结构（脚本化、参数化、固定随机种子、输出对齐）：3–7 天

最推荐二：Neural A\*（端到端学习规划的“高质量官方复现”入口）  
理由：官方提供 Docker、脚本、notebook；并配套 planning-datasets 数据生成仓库，适合你把“栅格风险场→规划”做成可扩展框架（可复现性强）。[\[57\]](https://github.com/omron-sinicx/neural-astar)  
时间估计：  
\- minimal demo 跑通：0.5–1 天  
\- 复现一个数据集（MP 或 mazes）训练/评估：2–5 天（取决于算力）  
\- 扩展实验（加入风险代价/不同地图分布）：1–3 周

最推荐三：ML4Floods（洪涝风险分割真实数据端的“工程型基线”）  
理由：提供 WorldFloods/相关论文链路与训练教程，并给出样例数据下载方式；非常适合你把“洪涝风险栅格场”做成真实世界数据基线，再与规划模块对接。[\[58\]](https://github.com/spaceml-org/ml4floods)  
时间估计：  
\- 跑通 sample 数据训练/评估：2–5 天  
\- 扩展到更大数据/多源：2–4 周（主要耗在数据与存储/IO）  
\- 与路径规划模块结合并做系统评估：2–4 周

## 结论与下一步建议

在你关心的“洪涝风险 + 栅格风险场 + 路径规划”交叉方向上，**最容易做出“完整可复现闭环”的策略**是：先用 DeepWay 或 Neural A _这类“自带数据生成/规划入口”的项目搭起可复现工程骨架（日志、配置、评测、可视化），再接入 ML4Floods / Sen1Floods11 等真实洪涝数据，把分割输出转为代价栅格并与 A_/Dijkstra 或 RL 环境打通；随后用 Gretel/DNAR 做“图上路径学习/最短路推理”的对照实验，形成方法覆盖面与论文叙事完整性。[\[59\]](https://github.com/fsalv/DeepWay)
